# Koder CLI 下载链接复制次数

[English](README.md) | 简体中文

专门统计 Koder CLI 下载链接复制按钮的成功使用次数。CLI 官网与 GitHub 引导进入的复制页共用这一累计值；同一个人复制三次，就增加三次。

复制内容始终为官方 [GitHub 最新发行页](https://github.com/KarmenLoop/koder-cli/releases/latest)。打开后可选择下载；本服务不镜像安装包，也不执行安装程序。

## 统计口径

浏览器确认剪贴板写入成功后才上报事件。每次新的成功操作生成一个随机事件 ID，网络重试沿用同一 ID，因此响应中断不会把同一次操作重复计入。查看统计、加载徽章、打开页面，以及复制失败，都不增加次数。

统计仅覆盖我们提供的按钮。GitHub 原生代码块复制、手动选择文字、独立人数和完成下载数，不属于此指标。成功状态由浏览器上报；公开服务无法独立核验系统剪贴板，也无法完全排除伪造的非浏览器请求。不虚构历史复制量。

待确认的事件保留在浏览器存储中；页面可见及网络恢复时继续提交。浏览器存储不可用时仍可复制，但请保持页面打开，直到统计保存完成。页面与未保存队列同时丢失时，这次上报可能丢失；界面不会提前宣称已记录。

## 运行与部署

版本 **1.0.0**，需要 Node **22 或以上**：

```sh
cd cli-copy-counter
npm ci
npm test
```

以本文件夹建立独立 Netlify 项目 `karmenloop-cli-copies`，保留配置文件。`@netlify/database` 配置独立 PostgreSQL 数据库并应用迁移。无需 GitHub 令牌；原主页和仓库流量项目、数据库继续独立运行。

只有当前已发布的正式部署可以写入。草稿部署不读取正式数据库，并拒绝复制上报。接口仅允许自有 CLI 官网与服务自身来源；更换域名时同步精确白名单，不使用通配写入来源。

把 `public/copy-client.mjs`、`public/cli-copy.mjs` 和 `public/cli-copy.css` 放入 CLI 官网 `assets/`，仅在中英文 CLI 介绍与下载页接入组件。GitHub README 通过带 `?from=github#copy-download-link` 的链接进入复制页，徽章读取同一计数。入口标记只说明来源，不代表认证后的身份。

## 接口与维护

- `POST /copies`：有大小限制的 JSON，仅含每次操作的随机 UUID 与 `source`（`github` 或 `website`）。新事件写入一份记录；重复 ID 保留原计数，来源冲突返回 409。
- `GET /stats.json`：只读累计值、来源分类及时间。空数据库返回真实的零；存储不可用返回 503。
- `GET /badge.svg?lang=en|zh-CN`：用于 GitHub README 的只读徽章。
- `GET /health`：可用性检查，不增加复制次数。

数据库保留每次操作的随机 ID、入口标记和服务端时间，不保存访客身份、IP、设备指纹或剪贴板内容。托管平台保留常规基础设施日志。网页可见时每十秒读取统计；GitHub 徽章经图片代理，显示可能滞后。

发布前运行测试，并核对真实浏览器复制、剪贴板 URL、重复操作、重试去重、只读请求、中英文及窄屏。先在隔离数据库验收；正式验收产生的复制属于真实事件，应在交付记录中说明。不提供公开清零或任意计数键接口。
