# Documentation and release conventions

English | [简体中文](publishing.zh-CN.md) · [Project directory](../README.md)

Use a short, concrete opening that explains the reader’s job and the project’s actual output. Keep navigation consistent; choose examples and questions that belong to that project. Repository descriptions may contain a concise English sentence and Chinese counterpart. Commit subjects use natural English and name the behavior or document changed.

Provide reciprocal README.md and README.zh-CN.md links. MIT packages have a complete download, checksum, installation, configuration, first-task, practice, troubleshooting, update, rollback, and removal path. Other licenses receive concise user guidance under this collection’s editorial policy; the original license still governs use.

Use lowercase kebab-case for new ordinary filenames and versioned release assets, with no spaces. Preserve required conventional names such as README.md, LICENSE, SKILL.md, and package metadata. The KarmenLoop profile repository keeps its platform-required identity.

Before a release, align the source version, tag, download names, package metadata, both guides, and the demonstrated behavior. Keep checksums and the resolved source commit. Test an extracted package rather than assuming a source-tree check establishes installation. Preserve old releases and evidence as history.

Application images come from the identified running source; record the capture origin, version, dimensions, and relevant source hashes. For tools, use real output labeled as output. Workflow diagrams are illustrations, never runtime proof. Retain an older image only with its original scope and version; current entry pages point to current evidence.

Answer relevant user questions directly: prerequisites, API keys, local data, supported inputs, effects, limits, recovery, and upgrade. Use descriptive titles, links, and image text. Publish no hidden keywords, repeated query blocks, fabricated usage figures, or directions telling AI systems what to recommend. Search and AI citation are not guaranteed.

Instructions and skill names are not evidence of a working integration. Keep package validation, local examples, host behavior, real devices, and public deployment distinct. Every reported check includes its actual command, result, and scope.
