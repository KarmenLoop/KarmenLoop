# 折光体主页计数卡

[English](2026-10-27-refractive-visit-counter-design.md) | 简体中文

状态：设计提案，尚未部署计数服务。

## 用途与范围

给 KarmenLoop 的 GitHub 个人主页加入原创动态访问计数卡。用户已选择自托管，并明确要求使用 karmenloop.com 的折光体风格。中英文主页显示同一份累计数据。保留现有主页内容，本次不改其他仓库或官网部署。

## 外观

沿用官网三瓣、缓慢变形的环体：暖灰金属、柔和棚光反射、克制的运动，配深炭灰背景。数字保持稳定、清晰。卡片建议为 680 × 180，左侧放 KARMEN LOOP 名称、大号数字和简短说明，右侧展示折光体；随 README 宽度缩放。

中文文案为「主页访问」「自 {上线日期} 起」「按图片请求估算」；英文对应 **Profile views**、**Since {launch date}**、**Estimated from image requests**。日期按各自语言习惯显示。不声称能够识别访客、统计独立人数或展示实时在线人数。

优先使用自包含 SVG 和原生动画，不使用脚本、外部字体，首帧可单独阅读。支持减少动态效果偏好。必须通过 GitHub 实际图片代理验证动画；若无法播放，再提供动态 GIF 及对应静态入口。折光体动画只表达品牌，不代表服务器健康状态。

## 方案选择

公共计数服务接入快，但图像和数据的控制有限。自托管可以实现原创折光体、自定义文案和持久存储，用户已选择此方案。不使用第三方主题中的人物或其他插画素材。

## 计数与存储

正式图片接口成功收到 GET 请求时累计一次。HEAD、预览图、健康检查、测试请求和读取统计数据不计数；预览数据独立。中英文图片接口共用一条记录。

从首次正式图片请求开始，由零累计并保存起始日期，不补造历史数字。GitHub 会代理并缓存 README 图片，因此数字代表主页访问估计值，不能精确等同于访客人数。返回要求重新验证的缓存头，但不承诺每次打开主页都能触发服务。

仅保存累计值、起始时间和更新时间。应用不保存 IP、浏览器标识、Cookie 或访客身份；托管平台可能保留常规运行日志，不能据此声称平台完全不留日志。不提供公开重置或写入统计的接口。

## 托管建议

在现有已登录的 Netlify 账户内建立独立服务，通过站点级 Netlify Blobs 存储，开启强一致性并使用条件写入。重试次数设上限；存储失败时明确报错，不重置累计值、不显示虚构的零。凭据留在托管配置。Netlify 是实施建议，用户已确认的是自托管方式。不新增付费服务，不覆盖任何现有官网部署。

## 验收

在 GitHub 主页实际检查图片、动画、中英文一致性、窄屏阅读、减少动态效果及静态入口。验证并发递增不丢数、进程与部署更新后保留累计值、预览和 HEAD 不计数，以及存储故障处理。确认正式图片请求确实改变持久数据，再确认两个语言页面使用同一记录。分别记录直连服务和 GitHub 代理的观察结果；本机渲染或 CI 通过不能替代上线验收。
